A general-purpose language that stays readable.

Quill is a small scripting language with classes, exceptions, closures, a module system, and its own web server, built so a program reads back close to plain English and a mistake gets a plain sentence with a line number instead of a stack trace.

Get started
$ quill

Code example

class Task:
    pull init(title):
        self.title = title
        self.done = false

    pull complete():
        self.done = true
        return f"{self.title} - done"

# first-class functions, real closures
let tasks = [Task("Write docs"), Task("Ship it")]
for t in tasks:
    print(t.complete())

Classes & exceptions

Multiple inheritance with a Python-style, C3-linearized MRO, and a super.method() that resolves correctly through deep chains and diamond hierarchies. try / except / finally catches your own errors and built-in ones the same way.

A module system

import "file.ql" as name pulls in another file's functions and values, so a program can grow past one file.

Ships its own web server

serve(port, handler) turns a Quill function into real HTTP responses, no framework required.

Install

Quill isn't on PyPI yet, so it installs from the source folder. Needs Python 3.10 or newer.

1

Clone the repo, then create a virtual environment and install it:

git clone https://github.com/riadworks/quill-lang.git
cd quill-lang
python -m venv .venv
.venv\Scripts\pip install -e .
2

That gives you a quill command. Run it with no arguments for a REPL, or point it at a script:

quill
quill script.ql
3

Want it on your PATH from any terminal instead of just an activated venv? Install it with pipx instead:

pipx install .

FAQ

What does Quill look like day to day?

Python-style indentation instead of braces, a pull keyword for functions, and real f-strings - f"hi {name}" interpolates, plain "hi {name}" never does. The code sample above is a complete, runnable example.

Do I need Python installed to use it?

For this build, yes - Quill's reference implementation is a tree-walking interpreter written in Python. A separate Rust port exists with the same language and no Python runtime required, at the cost of being a second codebase to keep in sync.

Is it fast?

It's a tree-walking interpreter, so it optimizes for reading and writing code, not raw throughput. If speed matters more than that tradeoff, the Rust build compiles to a native binary.

Can I actually build something with it, or is it just a toy grammar?

A handful of real, working apps ship with the project: a persistent CLI task manager, the same task manager as a website with a JSON API, a URL shortener, a text adventure, a password generator, and a number-guessing game. Each one ran and hit real bugs during development, which got fixed in the language itself.

What's missing?

Reflected operators (__radd__-style), a package manager, async/concurrency, and static typing are all left out for now, on purpose, to keep what exists solid rather than spreading thinner.
