Lesson 10

Exceptions

One try, one optional except, one optional finally — and a genuinely simple model underneath: raise can throw any value, and except catches both those and Quill's own built-in runtime errors the same way.

The basic shape

try:
    let result = risky_operation()
except e:
    print(f"something went wrong: {e}")
finally:
    print("cleanup always runs")

At least one of except or finally is required — try alone isn't valid. Naming a variable after except is optional too; leave it off (just except:) if you don't need the caught value. finally's body always runs, whether the try block succeeded, raised something caught by except, raised something that wasn't caught at all, or hit a return.

raise throws any value

There's no exception class hierarchy to define or inherit from — raise takes any expression at all, and whatever it evaluates to is exactly what except binds: 

try:
    raise "custom error"
except msg:
    print(f"got: {msg}")   # got: custom error

A string is the common case, but a number, list, map, or class instance all work exactly as well — except catches the value as-is, unchanged.

Built-in errors are catchable too

Division by zero, a bad list index, calling a function with the wrong number of arguments — every runtime error Quill itself can raise is catchable by the same except, with the caught value being the error's message as a string: 

try:
    let x = [1, 2]
    print(x[10])
except e:
    print(f"index error caught: {e}")
# index error caught: list index out of range

A worked example combining a return, an except, and a finally together: 

pull safe_divide(a, b):
    try:
        return a / b
    except e:
        print(f"caught: {e}")
        return nil
    finally:
        print(f"safe_divide({a}, {b}) done")

print(safe_divide(10, 2))   # 5, then "safe_divide(10, 2) done"
print(safe_divide(10, 0))   # "caught: division by zero", then "...done", then nil
Gotcha

There's no way to filter except by error type — no except ValueError:-style clause exists. A given try has at most one except, and it catches everything: your own raises and every kind of built-in runtime error, all the same way. If you need to react differently to different failures, inspect the caught value yourself (its type(), or the text of a built-in error's message) inside the one except block.

Uncaught exceptions

A raise (or a runtime error) with no matching try/except around it doesn't crash with a raw Python traceback — it's reported cleanly and the program stops, in a script with a non-zero exit code, or in the REPL as an Error: ... line so you can keep typing.

Check yourself

  1. What does except bind to when a built-in error like division by zero is caught?

    The error's message, as a plain string — the same thing you'd get from a user's own raise "some message".

  2. Can you write except ZeroDivisionError: to catch only division errors?

    No — Quill has no exception types to match against. A try has one except clause that catches everything; you'd check the caught value's content yourself if you need to branch on what went wrong.
