Lesson 7

Strings & Interpolation

Strings got a brief introduction back in Lesson 1. Here's the full picture, including exactly how {expr} interpolation is parsed — which explains some real sharp edges you'll otherwise hit by surprise.

Plain strings never interpolate

let name = "Ada"
print("Hello, {name}!")     # prints the literal text: Hello, {name}!
print(f"Hello, {name}!")    # prints: Hello, Ada!

The f prefix is what turns interpolation on, exactly matching Python's f-string convention. Without it, { and } are just ordinary characters — no escaping needed to use them literally in a plain string.

Escape sequences

EscapeMeans
\nNewline
\tTab
\"A literal double quote
\\A literal backslash

Both plain and f-strings support all four.

Gotcha

There is no single-quote string syntax at all — 'text' is a lex error, full stop, not an alternative way to write a string. This bites hardest inside an f-string's {...}, where reaching for a single quote out of Python habit (say, xs.join(', ')) fails even though it's nested inside an outer "..." — the interpolated fragment gets re-tokenized on its own, and it hits the same rule. Always use "...", even nested: f"{xs.join(", ")}" — see below for why that's not ambiguous.

Literal braces in an f-string

Since { starts interpolation in an f-string, writing one literally needs doubling — {{ and }}, the same convention Python uses: 

print(f"CSS rule: {{ color: red }}")
# CSS rule: { color: red }

let s = "  Hello World  "
print(s.trim().upper())        # "HELLO WORLD"
print(s.trim().split(" "))     # ["Hello", "World"]
print("abc".repeat(3))          # "abcabcabc"

Strings are indexed like lists (s[0], negative indexes from the end) but are immutable — there's no slice syntax either, so reach for slice(s, start, end) when you need a substring range.

How {expr} is actually parsed

It's worth knowing the mechanism, because it explains behavior you'd otherwise find surprising. When the lexer hits an unescaped { inside an f-string, it doesn't try to understand the expression at all — it just counts brace depth character by character until the matching }, completely ignoring quote characters along the way. That raw chunk of text is saved, and later handed to the lexer and parser again, on its own, as if it were a standalone expression.

That's exactly why this works, even though it looks like it shouldn't — a double-quoted string nested inside an interpolation, inside an outer double-quoted string: 

let person = {"name": "Ada", "age": 36}
print(f"{person["name"]} is {person["age"]}")
# Ada is 36

The outer string-scanner never sees those inner quotes as "its" closing quote, because while it's inside {...} it's just counting braces, not watching for " at all. It's also why any expression works inside the braces — a call, an index, arithmetic — not just a bare variable name.

Check yourself

  1. What does print("Total: {n}") print, given let n = 5?

    The literal text Total: {n} — no f prefix means no interpolation happens.

  2. Why does f"{xs.join(', ')}" fail?

    Quill has no single-quote string syntax anywhere, including inside an interpolated {...} fragment (which gets re-tokenized on its own). Use xs.join(", ") with double quotes instead.
