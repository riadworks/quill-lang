Lesson 14

Building Real Programs

Six full, working applications ship with the project's own source, built specifically to prove the language holds together on real programs rather than isolated examples. Each one found — and fixed — a genuine bug or gap in Quill itself. That's worth knowing both as a tour of what's possible and as a look at how the language actually got built.

apps/tasks/ — a persistent CLI task manager

cd apps/tasks && quill main.ql. An interactive menu-driven program that proved classes, modules, file I/O, and exceptions actually hold together — not six separate isolated examples, but one real program leaning on all of them together. Testing it by piping a full scripted session into quill (rather than only running scripts non-interactively) found a real bug: PowerShell prepends a UTF-8 BOM to piped stdin, which landed on the first input() call of a session and silently broke its first == comparison — fixed in the input() builtin itself. Removing a task by number also needed list.pop(i) with an index, which the language didn't have yet at the time.

apps/website/ — the same task manager as a website

cd apps/website && quill site.ql, then open http://127.0.0.1:8080/. Quill had no networking at all before this app — building it is what led directly to serve(port, handler) (Lesson 13). It also exposed a real gap while building the page's embedded CSS: f-strings had no way to write a literal { or }, so every CSS rule was getting misread as interpolation — fixed with the {{/}} escaping from Lesson 7. It has a GET /api/tasks JSON endpoint and a POST /api/wipe route gated by a sha256()-hashed admin key — comparing hashes, never plaintext.

apps/guess_game/ and apps/password_gen/

Two short, self-contained CLI programs (quill game.ql, quill gen.ql) exercising random/random_int/ sha256 outside of a test harness. The guess game found its own real design bug: piping a finite amount of input into a while true: loop means input() eventually hits end-of-input and returns "" forever (Lesson 12), so a naive "keep asking until you get a number" loop spins forever once stdin runs dry. Fixed at the app level with a bad-guess counter that gives up after five unreadable answers in a row.

apps/adventure/ — a small text adventure

Three rooms, one locked door, one item that ends the game — leaning on classes, maps as a room-to-exit graph, and comprehensions for filtering inventory and exits. Writing it surfaced the single-quote-string trap from Lesson 7 for real: xs.join(', '), easy to type out of Python habit, fails even nested inside an f-string's {...}.

apps/shortener/ — a URL shortener website

The same shape as apps/website/: POST /shorten generates a random code and persists the mapping as JSON, GET /<code> redirects, GET /api/links returns the raw map. It was proved out against a live running instance rather than just read over on the page — a real URL shortened, the redirect followed, and an unknown code confirmed to 404 instead of crashing the server.

Two bugs in the language itself

Building these surfaced real bugs in the interpreter, not just gaps in the standard library: a duplicated token-consumption bug in the class-body parser that broke every method definition, found by simply running the first classes example; and raised exceptions not inheriting from the same base error class as everything else, which meant an uncaught raise crashed the CLI with a raw Python traceback instead of the clean Error: ... message you'd get from any other error (Lesson 10). Both turned up from deliberately running the exact scenario, not from assuming the happy-path tests already covered it — worth remembering if you ever go looking through the interpreter's own source.
