Lesson 15

What's Next

That's the whole language — every keyword, every operator, every built-in function. This last lesson covers what's deliberately missing, and where to go from here.

What's deliberately not here

MissingWhat that means in practice
Multiple inheritanceclass C(A, B): isn't valid — one optional parent only.
Reflected operatorsNo __radd__-style fallback — an overload only fires with the instance on the left (Lesson 9).
A package managerNo third-party libraries to install — only what's in the standard library (Lesson 12) and your own .ql files (Lesson 11).
Async/concurrencyEverything runs on one thread, top to bottom — serve() included.
Static typingNo type annotations or compile-time type checking — every check happens at runtime (Lesson 2).

None of this is accidental — it's the project keeping its surface area small enough to stay solid and well-tested, rather than spreading thin over more features. All five are reasonable directions the language could grow in later.

There's no PyPI package yet

Quill installs from source only, the same way it did back in Lesson 1: 

git clone https://github.com/riadworks/quill-lang.git
cd quill-lang
python -m venv .venv
.venv\Scripts\pip install -e .

Where to go from here

  • Build something of your own. A CLI tool that reads/writes JSON and handles its own errors, a tiny website with serve(), or a small class hierarchy that leans on inheritance and operator overloading are all a good size to actually finish.
  • Read the shipped apps as real code, not just the lesson descriptions — Lesson 14 links straight to each one on GitHub.
  • Read the interpreter itself. It's genuinely small — about 2,500 lines across a dozen files (lexer, parser, AST, interpreter, and the built-in function tables) — small enough to read start to finish in an afternoon and come away actually understanding how a tree-walking interpreter works, not just how to use one.
  • Open the repo — file an issue, send a pull request, or just poke around.
