Lesson 5

Functions & Closures

pull is Quill's function-definition keyword — an original choice rather than borrowing def or fn. Otherwise, functions behave close to what you'd expect from Python: they're real values, they can be anonymous, and they close over their defining scope.

Defining and calling

pull add(a, b):
    return a + b

print(add(2, 3))   # 5

return with no expression (or falling off the end of the function with no return at all) gives back nil. There are no default parameter values and no variadic (*args-style) parameters — every call must supply exactly as many arguments as the function declares: 

add(1)
Error: 'add' expects 2 argument(s), got 1

Functions are values

A function can be assigned to a variable, passed as an argument, or returned from another function, whether it has a name or not: 

let double = pull(x):
    return x * 2

print(double(21))   # 42

When an anonymous function is passed inline as a call argument, though, its body has to be the single-line form. That's not a style choice — it's the only form available there, because the lexer stops emitting NEWLINE/indentation tokens at all once it's inside an unclosed (, so a multi-line indented block has no way to end: 

[1, 2, 3].map(pull(x): return x * x)

A let-assigned anonymous function doesn't have that restriction — it's not nested inside an open paren, so a normal indented body works fine (as double above already showed).

Closures

A function captures its enclosing scope, and can both read and mutate a variable from it after the outer function has already returned: 

pull make_counter():
    let count = 0
    pull increment():
        count = count + 1     # mutates the captured 'count' directly
        return count
    return increment

let counter = make_counter()
print(counter())   # 1
print(counter())   # 2

let other = make_counter()
print(other())     # 1 - a fresh call to make_counter() means a fresh 'count'

This works because count = count + 1 is a plain reassignment, and Lesson 2 already established that reassignment always walks up to find the existing variable — there's no special nonlocal/global keyword needed, unlike Python. Each call to make_counter() creates its own scope with its own count, so counter and other above don't interfere with each other.

Recursion

Ordinary recursion works exactly as expected — a function can call itself by name:

pull fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))   # 55

Check yourself

  1. Why must xs.map(pull(x): return x * x) be written on one line?

    Because it's inside the unclosed parentheses of the .map(...) call. The lexer only tracks indentation and emits NEWLINE tokens outside of parens/brackets, so an indented multi-line body has nothing to signal where it ends while inside them.

  2. If you call make_counter() twice and keep both returned functions, do they share one counter or have independent ones?

    Independent ones. Each call to make_counter() runs the function body fresh, creating a brand-new count variable in a brand-new scope each time — the two returned increment functions close over two different scopes.
