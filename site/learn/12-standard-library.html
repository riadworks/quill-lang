Lesson 12

Standard Library

Every top-level built-in function, in one place, grouped by purpose. Several of these were already introduced where they were most relevant (control flow, lists, maps) — this lesson is the reference version, plus everything that hasn't come up yet: files, JSON, hashing, and randomness.

Math

FunctionDoes
abs(n)Absolute value.
round(n) / round(n, digits)Rounds to the nearest integer, or to digits decimal places.
sqrt(n)Square root (error on a negative input).
floor(n) / ceil(n)Round down / up to the nearest integer.
sum(list) / min(list) / max(list)Over a list of numbers.
PIThe constant 3.141592653589793 (not a function — no parentheses).
Gotcha

round() uses banker's rounding (round-half-to-even) under the hood, the same as Python's round() — round(2.5) is 2, not 3. It's not a bug; it's the same tie-breaking rule Python uses to avoid statistically biasing rounded values upward.

Collections

Covered in full in Lesson 6 — the standalone forms, for reference:

FunctionDoes
len(v)Length of a string, list, or map.
range(n) / range(a, b) / range(a, b, step)Builds a list of numbers.
push(list, x) / pop(list) / pop(list, i)Same as .push()/.pop().
keys(map) / values(map) / items(map)Same as the map methods.
has(container, needle)Works on a map (key), list (element), or string (substring).
sorted(list)New sorted list; needs all-comparable elements.
slice(seq, start, end)Substring or sub-list, since there's no [a:b] syntax.
enumerate(list)List of [index, value] pairs.
zip(a, b)List of [a_item, b_item] pairs, stopping at the shorter list.

Input & output

FunctionDoes
print(...)Any number of arguments, space-joined, each converted with str().
input([prompt])Reads one line from stdin; returns "" at end-of-input rather than erroring.
read_file(path)Returns the whole file as a string.
write_file(path, content)Overwrites (or creates) a file with str(content).
file_exists(path)Boolean.

Because input() returns "" forever once input runs out (rather than raising an error), a while true: loop that keeps asking for input needs its own escape hatch — a bad-answer counter, for instance — or it spins forever once a piped input file is exhausted.

JSON

FunctionDoes
json_encode(v) / json_encode(v, pretty)Serializes a string/number/bool/nil/list/map to a JSON string. pretty (any truthy value) indents it.
json_decode(s)Parses a JSON string back into Quill values.

Quill's own runtime values already line up exactly with what JSON can represent — the one thing json_encode can't handle is a class instance, function, or class itself; convert an instance to a plain map first if you need to serialize it.

Hashing & randomness

FunctionDoes
sha256(s)Hex-encoded SHA-256 hash of a string.
password_hash(password)Salted PBKDF2-HMAC-SHA256 hash, as a self-contained string.
password_verify(password, hash)Checks a password against a password_hash() result, using a constant-time comparison.
random()A float in [0, 1).
random_int(lo, hi)A random integer, inclusive of both lo and hi.
random_choice(list)One random element.
shuffle(list)A new shuffled list — the original is left untouched.

sha256 exists so a fixed, high-entropy secret — an API key, an admin token — never has to be stored or compared as plaintext: hash it once, and compare hashes from then on. See Lesson 14 for that pattern in a real route.

Gotcha

sha256 is the wrong tool for an actual user-chosen password: it's fast and unsalted, which is exactly what makes it vulnerable to precomputed rainbow tables and brute-force cracking once a database of hashes leaks. For a real password, use password_hash(password) to store it and password_verify(password, hash) to check a login attempt — both are built on salted PBKDF2-HMAC-SHA256 with a constant-time comparison, so two hashes of the same password never match each other and checking one can't be sped up by timing how long the comparison takes.

Gotcha

Unlike Python's random.shuffle(), which shuffles a list in place and returns nil, Quill's shuffle(xs) leaves xs alone and returns a new, shuffled list. Write xs = shuffle(xs) if you want the variable itself updated — the same pattern as .sort() from Lesson 6.

Check yourself

  1. What does shuffle(xs) do to xs itself?

    Nothing — it returns a new shuffled list and leaves xs exactly as it was.

  2. What's the difference between zip(a, b) and enumerate(a)?

    enumerate(a) pairs each element of a with its own index: [[0, a[0]], [1, a[1]], ...]. zip(a, b) pairs up elements from two separate lists by position: [[a[0], b[0]], [a[1], b[1]], ...], stopping at whichever list is shorter.
