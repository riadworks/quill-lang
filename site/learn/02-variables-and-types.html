Lesson 2

Variables & Types

Quill is dynamically typed: a variable doesn't have a declared type, only the value it currently holds does. This lesson covers declaring variables and the six kinds of values Quill programs work with.

let declares, plain assignment reassigns

let introduces a brand-new variable. Once it exists, drop let to change its value: 

let score = 90
score = 95   # reassigns the existing 'score'

Assigning to a name that was never let-declared is a runtime error, not a silent global creation: 

age = 30
Error: cannot assign to undefined variable 'age' (use 'let' to declare it first)

This is deliberate: it catches typos immediately instead of quietly creating a new variable when you meant to update one you already had. It's also what makes the closures in the next lesson work — mutating a captured variable needs no special keyword, because name = value already unambiguously means "the existing one."

Variable names start with a letter or underscore, followed by any mix of letters, digits, and underscores — the same rule as most C-family and Python-family languages.

Numbers

Quill has one number type, not separate int/float types you have to think about. Whichever you write is whichever you get, and arithmetic promotes automatically: 

print(type(5))       # number
print(type(3.14))    # number
print(10 / 3)        # 3.3333333333333335  - / always produces a float
print(10 // 3)       # 3                   - // floors

Scientific notation works too (1e10, 2.5e-3). One more detail that matters once you start printing things: a float that happens to hold a whole number prints without a trailing .0 — sqrt(16) shows 4, not 4.0.

Strings, booleans, nil

"text" is a string literal (full coverage, including interpolation, is in Lesson 7). true and false are the boolean literals. nil is Quill's "no value" — the equivalent of None in Python or null elsewhere. 

let found = false
let result = nil

Lists and maps

Rounding out the six value types are lists ([1, 2, 3]) and maps ({"key": "value"}) — Quill's two collection types, both mutable, both covered in full in Lesson 6.

Truthiness

Anywhere a condition is expected (if, while, and/ or), a value is treated as either truthy or falsy. Falsy covers exactly: nil, false, the number 0 (or 0.0), and an empty string, list, or map. Everything else — including negative numbers and non-empty strings like "false" — is truthy. 

if "": print("you won't see this")
if "0": print("but you will see this")   # non-empty string is truthy
if -1: print("and this")                      # -1 is truthy, only 0 is falsy

Converting between types

Four built-in functions cover conversions and inspection:

FunctionDoes
type(v)Returns a string naming v's type: "nil", "bool", "number", "string", "list", "map", "function", "class", or the class name for an instance.
str(v)Converts anything to its printable string form (the same conversion print() uses internally).
num(v)Converts a numeric string to a number; numbers pass through unchanged. Raises a runtime error on anything else.
bool(v)Returns v's truthiness as a real boolean.
print(num("42") + 8)     # 50
print(str(3.5) + "!")     # "3.5!"
print(bool(0))            # false
Gotcha

+ never auto-converts for you: "score: " + 5 raises "cannot add string and number (use str() to convert first)". Write "score: " + str(5), or reach for an f-string instead (f"score: {5}") — see Lesson 7.

Check yourself

  1. What does type(nil) return? What about type(3.0) vs. type(3)?

    type(nil) is "nil". type(3.0) and type(3) are both "number" — Quill doesn't expose a separate int/float distinction through type().

  2. Is bool([]) true or false? Is bool([0])?

    bool([]) is false — an empty list is falsy. bool([0]) is true — it's a non-empty list (a list containing one falsy number is still itself a non-empty, truthy list).
