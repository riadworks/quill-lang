Lesson 3

Operators & Expressions

Most of this will look familiar from any C-family or Python-family language. The parts worth slowing down for are precedence, and two places where Quill quietly does not match Python.

Arithmetic

OperatorMeaningExample
+Addition (also string and list concatenation)2 + 3 → 5
-Subtraction5 - 3 → 2
*Multiplication4 * 2 → 8
/Division — always returns a number with a fractional part when needed7 / 2 → 3.5
//Floor division7 // 2 → 3, 5 // -2 → -3
%Modulo — sign follows the divisor, like Python-5 % 3 → 1
**Exponentiation, right-associative2 ** 3 ** 2 → 512 (that's 2 ** (3 ** 2))

Dividing or floor-dividing or taking the modulo of anything by zero is a clear runtime error ("division by zero"), not inf or a crash with a Python traceback.

Gotcha

Unary minus binds tighter than ** in Quill — the opposite of Python. -2 ** 2 is 4 here (it parses as (-2) ** 2), where Python's -2 ** 2 is -4 (Python parses it as -(2 ** 2)). If you want the Python reading, parenthesize it yourself: -(2 ** 2).

Comparison

OperatorMeaning
== / !=Equal / not equal. Works on any two values — see below.
< > <= >=Ordering. Numbers only.

== and != compare structurally: two lists are equal if they're the same length with equal elements in order, two maps are equal if they have the same keys mapping to equal values, and numbers compare by value regardless of int/float. </>/<=/>=, on the other hand, only work between two numbers — there's no built-in ordering for strings, so "apple" < "banana" is a runtime error, not alphabetical comparison. (A class can define its own via __lt__ and friends — see Lesson 9.)

Gotcha

Quill has no chained comparisons. 1 < 2 < 3 doesn't mean "is 2 between 1 and 3" the way it does in Python — it's parsed left to right as (1 < 2) < 3, which evaluates the first comparison to true and then tries to compare that boolean against a number with <, which is a runtime error ("cannot use '<' on bool and number"). Write it out with and instead: 1 < 2 and 2 < 3.

Logical operators

and, or, and not are words, not symbols (there's no &&/||/!). and and or short-circuit and hand back one of their actual operands rather than always forcing a boolean — the same useful idiom Python uses for defaults: 

print("" or "default")     # "default" - left side is falsy, so 'or' returns the right side
print(nil and 5)         # nil       - left side is falsy, so 'and' short-circuits and returns it
print(not false)          # true      - 'not' always returns a real boolean

Precedence from loosest to tightest binding: or, then and, then not, then the comparisons, then +/-, then *//////%, then unary -, then **. In practice this means not a == b reads as not (a == b), and a and b or c reads as (a and b) or c — parenthesize anything you're not sure of rather than relying on memorizing the table.

Ternary expressions

A single-expression conditional, in the same X if COND else Y order Python uses: 

let label = "big" if x > 5 else "small"

It's the loosest-binding expression form of all, and it chains by nesting in the else branch, so this reads the way you'd expect: 

let grade = "A" if score >= 90 else "B" if score >= 80 else "C"

Augmented assignment

+=, -=, *=, and /= exist and do the obvious thing. Notably, there is no //=, %=, or **= — those simply aren't tokens the lexer recognizes, so write them out in full: x = x // 2 instead of x //= 2. 

let counter = 0
counter += 5
counter *= 2
print(counter)   # 10

Check yourself

  1. What does print(-2 ** 2) print in Quill, and how is that different from Python?

    It prints 4. In Quill, unary minus binds tighter than **, so this is (-2) ** 2. In Python the same expression is -4, because Python's unary minus binds looser than **.

  2. Why does "a" < "b" raise an error in Quill?

    Because </>/<=/>= only work on numbers in Quill — there's no built-in string ordering. Only == and != work across all types.
